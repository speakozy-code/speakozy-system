# نشر Speakozy على Firebase Hosting بعد المراجعة

> هذه التعليمات **لا تنشر تلقائيًا**. نفّذها فقط بعد قبولك نسخة المعاينة. لا تتضمن هذه الخطوات تطبيق قواعد Firestore أو ترحيلًا للبيانات. يتطلب تفعيل دور المسوّق إعداد مستند `hub/marketing` وقاعدة القراءة المقترحة في `FIRESTORE-MARKETER-PROPOSAL.md` وموافقة المالك قبل أي نشر لهذه القواعد.

## ما الذي ستستبدله؟

ملفات واجهة الاستضافة فقط:

- `public/system-preview.html`
- `public/index.html`
- `public/login.html`
- `public/assets/`

تبقى `firebase.json` و`firestore.rules` و`firestore.indexes.json` كما هي.

## 1. نزّل حزمة التسليم مباشرة في Cloud Shell

استخدم أمر `curl` الذي يأتي مع رابط الحزمة في رسالة التسليم؛ لا يلزم تنزيل الملف إلى جهازك أو رفعه يدويًا. يجب أن ينشئ الأمر الملف `~/speakozy-firebase-build.zip` ثم يتحقق من سلامة ZIP قبل متابعة الخطوة التالية.

## 2. نفّذ النسخ الاحتياطي والاستبدال والبناء

```bash
set -euo pipefail
cd ~/speakozy-site
STAMP="$(date +%Y%m%d-%H%M%S)"
mkdir -p "backups/ui-$STAMP"
cp -a public "backups/ui-$STAMP/public"

unzip -o ~/speakozy-firebase-build.zip -d /tmp/speakozy-build
cp -a /tmp/speakozy-build/dist/. public/

# تحقق قبل أي نشر: الملفات الثلاثة والمسارات يجب أن توجد.
test -f public/index.html
test -f public/login.html
test -f public/system-preview.html
test -d public/assets
echo "تم تجهيز الواجهة. النسخة السابقة محفوظة في backups/ui-$STAMP"
```

## 3. راجع محليًا ثم انشر Hosting فقط

```bash
firebase hosting:channel:deploy review --expires 7d
# افتح رابط المراجعة الناتج، وسجل دخول بحسابات المالك/الأدمن/المدرس.
# عند قبولك للمراجعة فقط:
firebase deploy --only hosting
```

## استرجاع الواجهة السابقة

```bash
set -euo pipefail
cd ~/speakozy-site
# استبدل STAMP بتاريخ النسخة التي تريد إرجاعها.
rm -rf public
cp -a "backups/ui-STAMP/public" public
firebase deploy --only hosting
```

## ملاحظات التحقق

- تأكد أن حساب المدرس يرى «جروباتي» والحضور والساعات فقط.
- تأكد أن الأدمن لا يرى المالية أو إجمالي الطلاب الكلي ولا يضم التصدير/الاستعادة بيانات مالية؛ المالك وحده يراها.
- تأكد أن الأرشيف لا يغيّر إجمالي الطلاب أو الإيرادات أو الريتينشن أو الساعات أو تقارير اليوم أو الإشعارات أو البحث؛ السجلات تظل في الأرشيف/النسخ الاحتياطية للاستعادة دون إجماليات محسوبة منها.
- تأكد أن نقل طالب إلى Private مشغول يُرفض، وأن كل جلسة Private لطالب واحد فقط.
- من رأس عمود جلسة، أجّل جلسة مستقبلية ثم راجع المعاينة؛ يجب أن تنتقل الجلسات النشطة التالية لأيام الجروب نفسها، ويبقى إجمالي 8 جلسات نشطة كما هو، مع تمديد/إعادة نهاية الجروب عند الحاجة. لا تُقبل الإزاحة إذا كانت جلسة متأثرة عليها علامة حضور أو غياب.
- اختبر إلغاء الجلسة واستعادتها من رأس العمود نفسه، وحاضر/غائب فقط وإعادة الضغط لمسح العلامة وترك الخانة بلا علامة؛ تأكد أن الملغاة تظل ظاهرة في جدولي الحضور والمدرس ولا تدخل في الساعات.
- جرّب الأرشفة والاستعادة والحذف النهائي على بيانات اختبار فقط، وتأكد من اختفاء سجلات الحضور المركزية المرتبطة بالحذف؛ لا تستخدم بيانات طلاب حقيقية لهذا الاختبار.
- لا تنفّذ `firebase deploy --only firestore:rules` ضمن هذا النشر.
