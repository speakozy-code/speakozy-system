# مهام إعادة بناء Speakozy

البنود المحددة بـ `[x]` لها دليل تنفيذ في نسخة المعاينة؛ البنود المحددة بـ `[ ]` ما زالت قيد الإصلاح أو التحقق. اختبارات السلوك قابلة لإعادة التشغيل عبر `pnpm test`. لا يعني ذلك نشرًا إلى Firebase الحي؛ النشر يبقى خطوة مراجعة منفصلة بموافقة صريحة.

## 1. هيكل التطبيق والمصادقة والأدوار
- [x] بناء هيكل واجهة متجاوب جديد من الصفر وفق Concept A المختار: هيدر منظم وثابت للكمبيوتر والهاتف؛ كلمة SPEAKOZY بالإنجليزية في يسار الهيدر؛ قائمة جانبية يمين الكمبيوتر تتحول إلى قائمة هاتف؛ بطاقات وجداول ونماذج وحواف ومسافات متناسقة، وإشعارات لا تغطي المحتوى.
- [ ] عند عرض هاتف/تابلت حتى 980px تتحول القائمة الثابتة إلى درج قبل أن تضيق مساحة المحتوى؛ أدوات البحث والفلاتر والأزرار تلتف داخل عرض الصفحة في جميع التبويبات بلا قص أو خروج أفقي غير مقصود، وتظل الجداول الطويلة قابلة للتمرير أفقيًا.
- [x] في Demo، تحقق أن بيانات الطالب وبيانات جروب Private قابلة للتعديل والحفظ دون اتصال Firebase؛ ثم استُبدل الإجراءان بزر واحد كما هو محدد في بند Private أدناه.
- [x] الحفاظ على تسجيل الدخول الحالي عبر Firebase Email/Password، وإرجاع غير المسجل إلى login، وتسجيل الخروج، وربط الجلسة ببيانات الدور الحالية؛ لا يُستخدم اختيار دور محلي كبديل للمصادقة أو الصلاحية.
- [x] عند تعذر اتصال Firestore («client is offline») يعيد التطبيق محاولة الاتصال حتى ثلاث مرات، ويتيح زر «إعادة المحاولة»، ويعيد المحاولة عند عودة اتصال المتصفح؛ ويعرض رسالة تفرّق بين انقطاع الشبكة ورفض الصلاحية.
- [x] إبقاء صلاحيات الأدوار واضحة: الأدمن يملك الصلاحيات التشغيلية والأرشيف والريتينشن والأمان، ولا تظهر له المالية أو إجمالي الطلاب الكلي؛ المالك يرى المالية وإجمالي الطلاب الكلي؛ المدرس يرى الجروبات والحضور والساعات المسندة إليه. عند دور Admin الصريح لا يقرأ التطبيق مستند `hub/finance`، ويصفّر المالية من الحالة والنسخ والاستعادة والتصدير؛ تبقى للمالك فقط. لا تغيير لقواعد Firestore أو مخطط البيانات دون موافقة مستقلة.
- [x] إبقاء أسماء ومسارات صفحات الدخول والرئيسية المتوافقة مع الاستضافة الحالية، وعدم النشر على Firebase الحي قبل مراجعة المعاينة وموافقة المستخدم الصريحة.

## 2. الرئيسية والتقرير اليومي
- [x] إعادة تصميم بطاقات ومؤشرات الرئيسية والتقرير اليومي مع الحفاظ على بيانات الجروبات والراوندات والمدفوعات والتجديد والليدز والغياب والمتابعات والاختصارات الحالية.
- [x] إجمالي الطلاب الحاليين في الرئيسية يحسب طلاب الجروبات والـPrivate معًا، ويظل مستقلًا عن مؤشرات الريتينشن.
- [x] أرقام الإيرادات في الرئيسية تطابق طريقة الحساب الحالية في صفحة الإيرادات والمصروفات.
- [x] إبقاء محتوى ومقاييس ومخاطر تقرير اليوم الحالي كما هي، وإضافة جدول لكل جلسات التاريخ المحدد يشمل جميع المدرسين والجروبات والـPrivate مع المدرس، والنوع، واسم الجروب/الطالب، والوقت، وحالة الإلغاء عند وجودها.
- [x] يعرض ملخص «جروبات اليوم» جميع الجروبات والـPrivate المجدولة في ذلك اليوم دون الاقتصار على أول أربع مجموعات.
- [x] الحفاظ على فلترة المؤشرات والصلاحيات بحيث لا تظهر بيانات المالية أو إجمالي الطلاب للأدوار غير المصرح بها.
- [x] لا يدخل أي سجل مؤرشف في إجمالي الطلاب أو الجروبات والـPrivate الحالية، الإيرادات والمصروفات، الريتينشن، ساعات المدرسين، تقارير اليوم والغياب، الإشعارات، البحث أو قائمة الطلاب السابقين؛ يشمل ذلك الجروب والـPrivate والطالب والراوند والليد والحركة المالية المؤرشفة. تبقى السجلات محفوظة وقابلة للاستعادة في تبويب الأرشيف والنسخ الاحتياطي، لكن لا تعرض الواجهة أو ملفات الأرشيف الإجمالي أعدادًا محسوبة منها، ولا تحولها إلى بيانات نشطة.

## 3. الراوندات والجروبات والطلاب والـPrivate
- [x] الحفاظ على إنشاء وتعديل وإيقاف وأرشفة واستعادة الراوندات والجروبات، وإدارة الطلاب ومستوياتهم ومدفوعاتهم والمتبقي وملاحظاتهم وتجديداتهم، والنسخ/النقل بين الجروبات، وخصائص الأرشفة والاسترجاع والحذف النهائي المؤكد.
- [x] يسمح بفتح جروب واحد فقط في كل مرة؛ فتح جروب آخر يغلق الجروب المفتوح.
- [x] اسم الجروب في الإضافة والتعديل اختيار من E1 إلى Advanced 3؛ لا يوجد عدد مستويات على الجروب. اختيار 1 أو 2 أو 3 أو 4 أو 6 يخص عدد المستويات المدفوعة لكل طالب، ويظهر في نموذج إضافة الطالب/Private وداخل بطاقة الطالب وتعديل الدفع للمالك فقط.
- [x] الجروب الذي يغطي فترة ممتدة مثل 4–6 مساءً يظهر كتلة واحدة على الفترة كلها وليس عنصرًا متكررًا لكل ساعة.
- [x] لكل جروب لون ثابت ومميز، ويظل اللون نفسه عند ظهوره في أيام متعددة.
- [x] أوقات الجدول تستخدم AM/PM، مع وضوح الأيام والبداية والنهاية.
- [x] تصغير اسم الطالب على الهاتف مع إبقاء الاسم مقروءًا.
- [x] جدول الحضور والغياب ومواعيد الجلسات لا تظهر داخل صفحات الجروبات أو الراوندات أو تبويب Private؛ كل عرض الجلسات وتعديل المواعيد والإلغاء والاستعادة يكون في تبويب الحضور والغياب فقط.
- [x] عند إلغاء جلسة تبقى موسومة «ملغاة»، ولا تدخل في ترقيم الجلسات النشطة؛ الجلسة النشطة التالية تصبح مكانها رقميًا، ويُضاف موعد جديد في آخر أيام الجروب المحددة ليعود العدد إلى 8 جلسات نشطة حتى لو امتد تاريخ النهاية. عند استعادة الملغاة يُحذف الموعد البديل الأخير إذا لم يكن عليه حضور/غياب.
- [x] إذا كان جدول قديم يحتوي أقل من 8 جلسات نشطة، يقترح جدول الحضور المواعيد الناقصة حسب أيام الجروب ويعرضها داخل الجدول مع زر «حفظ 8 جلسات» للمالك/الأدمن؛ مجرد فتح الجدول لا يحفظ تغييرات على Firestore.
- [x] إبقاء الـPrivate مسارًا مستقلًا في الجروبات والمدفوعات والمتابعة والأرشيف وعدم تحويله إلى جروب عادي؛ كل جروب Private جديد لطالب واحد فقط، ويُنشأ سجل الطالب مع الجروب أو يُضاف طالب واحد إلى جروب Private فارغ، ولا يُسمح بإضافة طالب ثانٍ للجروب نفسه أو نقل طالب إلى جروب Private مشغول. إذا وُجد جروب قديم مرتبط بأكثر من طالب يظهر تنبيه ولا يحدث ترحيل تلقائي.
- [x] تبويب Private يعرض كل Private كجروب كامل لطالب واحد دون أكورديون طلاب متداخل؛ عنوان الجروب اسم الطالب، وتظهر بياناته ومستواه ورقم هاتفه وأيام الجروب والمدرس والوقت وتاريخا البداية والنهاية. الظاهر في الركن أيقونة إضافة Private فقط؛ الضغط عليها يفتح نموذج الإنشاء كنافذة، ولا يبقى النموذج الكبير ظاهرًا داخل الصفحة ولا يظهر السجل القديم الفارغ على شكل نموذج. إخفاء السجل الفارغ لا يحذف بياناته. النموذج ينشئ الجروب والطالب معًا؛ يبقى طالبًا واحدًا نشطًا فقط في كل جروب.
- [x] لا يظهر جدول مواعيد الجلسات أو الحضور داخل صفحة Private؛ تعرض بيانات الجروب الثابتة، بينما تعرض جلساته وحضوره في تبويب الحضور والغياب.
- [x] في Private يظهر زر «تعديل بيانات Private» واحد يفتح نموذجًا موحدًا لتعديل بيانات الطالب (الاسم والهاتف والمستوى والملاحظة) وبيانات الجروب (الأيام والمدرس والوقت وتاريخ البداية والنهاية) معًا؛ تغيير الأيام/تواريخ الفترة يتطلب تأكيدًا، وتظل كل جلسة عليها حاضر/غائب في تاريخها الأصلي، ولا تُنقل علامتها إلى موعد جديد؛ يعاد توليد المواعيد غير المسجل عليها حضور وتبقى الإلغاءات القديمة ظاهرة مع 8 جلسات نشطة على الأقل. تبقى تغييرات موعد الجلسة المفردة من تبويب الحضور والغياب. إذا لم تتسع الفترة المختارة للثماني، يُمدد تاريخ النهاية تلقائيًا، أما إذا كان أبعد فيحتفظ به. تحقق Demo بتغيير الأيام وتاريخ البداية بعد تسجيل حاضر: بقيت العلامة على 18 أكتوبر وأعيد توليد 8 جلسات. وتغطي اختبارات المجال علامة بتاريخ جلسة ملغاة دون إحياء الجلسة، مع توليد بديل، وبقاء تاريخ نهاية أبعد أو تمديد الأقصر عند الحاجة؛ لم يتصل الاختبار بـFirebase.

## 4. الليدز والعملاء وتحديد المستوى والمتابعات
- [x] تسمية تبويب «العملاء الجدد» تصبح «عملوا تحديد مستوى».
- [x] عند تغيير ليد إلى حالة تحديد مستوى ينتقل تلقائيًا إلى تبويب تحديد المستوى.
- [x] في قوائم الليدز والعملاء الجدد/تحديد المستوى، الحالات «مكتمل»، «لا يحتاج متابعة»، و«غير مهتم» تظهر في نهاية القائمة وتترتب فيما بينها وفق أولوية التصنيف.
- [x] الحفاظ على إضافة وتعديل وتصنيف وتحويل الليد إلى طالب أو Private/جروب، وتحديد المتابعة القادمة وتاريخها وملاحظاتها وأرشفتها واستعادتها.

## 5. الحضور والغياب والتقارير
- [x] تبويب الحضور يعرض مرشح المدرس للمالك/الأدمن، ومرشح الراوند، ثم أسماء الجروبات والـPrivate المسندة للمدرس المحدد؛ حساب المدرس يرى مجموعاته والـPrivate المسندة إليه فقط.
- [x] الضغط على اسم الجروب أو Private يفتح تفاصيله وجدول حضوره، ويظهر الاسم الكامل بوضوح.
- [x] عند تعديل تاريخ جلسة من عمودها في جدول الحضور، تُعاد جدولة الجلسات النشطة التالية تلقائيًا حسب أيام الجروب المحددة (مثل السبت/الثلاثاء أو الأحد/الأربعاء)، مع الحفاظ على العدد المقرر من الجلسات (8 عند وجود 8 جلسات نشطة). تظهر معاينة بالتواريخ القديمة والجديدة ويُطلب التأكيد داخل قسم الجدول؛ يُمدد أو يُعاد تاريخ نهاية الجروب حسب الحاجة. لا تتحرك الجلسة المتأثرة إذا كان لها حضور أو غياب مسجل، وتظل الجلسات الملغاة ومواعيدها ظاهرة ومحفوظة.
- [x] يتوفر إلغاء الجلسة مع إضافة موعد بديل عندما يسمح تاريخ الجروب، واستعادة الملغاة من أعمدة جدول الحضور نفسه؛ عند الاستعادة يحافظ الجدول على 8 جلسات نشطة ويحذف البديل الأخير إذا زاد العدد، ويرفض الاستعادة برسالة واضحة إذا كان البديل الأخير عليه حضور/غياب مسجلًا بدل ترك 9 جلسات نشطة. لا توجد لوحة أو قائمة إدارة منفصلة تحت الجدول.
- [x] تبقى الجلسة الملغاة ظاهرة وموسومة «ملغاة» في جدول الحضور وجدول جلسات المدرس، ويظل احتساب ساعات المدرس مستبعدًا لها؛ يظهر الاسم الكامل للجروب في الجدولين.
- [x] يظهر شريط تمرير أفقي واضح بجوار جدول العلامات ويتيح سحبًا مباشرًا حتى الجلسة الثامنة على الهاتف والكمبيوتر، مع استمرار دعم السحب/التمرير باللمس.
- [x] تصغير أعمدة الاسم والجلسات وأدواتها كي تظهر الجلسات الثماني النشطة معًا على شاشة الكمبيوتر المعتادة؛ يظل شريط السحب الأفقي فعالًا على الهاتف أو عند ظهور أعمدة جلسات ملغاة إضافية.
- [x] لكل خانة خيارا تسجيل فقط: صح/حاضر أو غلط/غائب؛ إعادة الضغط على الاختيار المحدد تمسح العلامة وتحفظ الخانة بلا علامة.
- [x] حفظ أو إلغاء علامة الحضور لا يعيد المستخدم إلى أول الجروبات أو أول الجدول ولا يفقد موضع التمرير.
- [x] تظهر الجروبات والـPrivate المسندة للمدرس في الحضور والغياب، مع استمرار مزامنة سجلاتها بين المدرس والأدمن والمالك.
- [x] لا تظهر أزرار «م» أو «ع»؛ تظل أي سجلات تاريخية قديمة محفوظة من دون إتاحتها كخيارات تسجيل جديدة.
- [x] الحفاظ على سجل الحضور والغياب وتقارير الجلسات والخانات التي لم يُدخل حضورها وتنبيه حد الغياب الحالي.

## 6. حسابات المدرسين وساعاتهم
- [x] عند إنشاء حساب مدرس أو تحديثه تُزامن بياناته وإسناداته تلقائيًا مع واجهات المالك والأدمن والمدرس وفق آلية النظام الحالية.
- [x] يستطيع المالك أو الأدمن إضافة مدرس وأرشفة مدرس من تبويب ساعات المدرسين ثم استعادته من الأرشيف. الأرشفة تخفيه من خيارات التعيين الجديدة، ولا تحذف حساب Firebase أو بيانات الساعات أو التكليفات التاريخية؛ تظل الجروبات الحالية محفوظة وتظهر سجلاتها، وتبقى أرشفة المدرس واضحة كأرشفة لا «إيقاف عن العمل». اختبارات الدومين تغطي الأرشفة/الاستعادة وحجب التعيين وحفظ الساعات؛ وفي Demo ظهر المدرس بالأرشيف واستعيد مع بقاء تكليفاته وتقاريره كما هي.
- [x] اختيار المدرس في نماذج إنشاء/تعديل الجروب والـPrivate قائمة منسدلة من المدرسين النشطين والحسابات المتزامنة، لا حقل نص حر؛ الاسم القديم/الموقوف يظل ظاهرًا كخيار محفوظ في تعديل سجل قائم فقط، ولا يظهر في نموذج إنشاء جديد.
- [x] يستطيع الأدمن أو المالك إدخال ساعات العمل الأسبوعية لكل مدرس.
- [x] تبويب «جروباتي» للمدرس يعرض الجروبات والـPrivate المسندة إليه معًا، إضافة إلى جدول أسبوعي بالتفصيل حسب اليوم والوقت.
- [x] الضغط على اسم جروب في تفاصيل ساعات المدرس يفتح نفس الجروب تحت الراوند أو تبويب Private المناسب؛ الجروب المؤرشف أو التابع لراوند غير نشط يمكن فتح سجله من الأرشيف/صفحة الراوند، من دون إدخاله في ساعات الجروبات النشطة.
- [x] حساب ساعات المدرس وجدوله الأسبوعي من الجروبات التابعة لراوندات نشطة وغير مؤرشفة فقط، مع استبعاد الجروبات والراوندات المؤرشفة أو غير النشطة؛ تُحسب جلسات الـPrivate غير المؤرشفة ضمن شهرها، وتُستبعد الجلسات الملغاة. يستخدم الحساب الشهري وجدول جلسات المدرس والتقرير اليومي نفس الجلسات الفعلية حتى 8، ولا ينشئ تكرارات تاسعة لمجرد أن تاريخ نهاية الجروب أبعد؛ الجداول القديمة الناقصة تعرض اقتراحًا متطابقًا حتى حفظه. الحساب الشهري من يوم 1 حتى آخر يوم فعلي (30 أو 31 أو غيره)؛ خمس جلسات × ساعتين = 10 ساعات.
- [x] الحفاظ على بيانات ساعات المدرس وقيود القراءة والكتابة حسب دوره، وعدم تغيير معرّفات الجروبات/الطلاب أو حقول الإسقاطات دون ترحيل وموافقة.

## 7. الإشعارات والبحث والنسخ
- [x] إشعار الليد/الطالب يعرض خيارَي «تم» و«نسخ الرقم» فقط.
- [x] عند قرب انتهاء راوند جروب يظهر نص «الراوند بتخلص ابعت فولو اب»، مع خيار «تم» وخيار «اعرض الجروب» الذي يفتح الجروب وأرقامه.
- [x] الحفاظ على لوحة إشعارات المتابعات اليومية، البحث الشامل، اختصارات لوحة المفاتيح، نسخ الأرقام، إجراءات المتابعة وتاريخها، وحالة النسخ الاحتياطي.

## 8. المالية والريتينشن
- [x] الإيرادات في الرئيسية والكشف الشهري تشمل كل الجروبات والراوندات غير المؤرشفة حتى لو كانت متوقفة (`on=false`)، وتستبعد ما أُرشف فعلًا من الجروب أو الراوند أو الطالب. يظل الشهر محسوبًا من تاريخ بداية الجروب لعدم وجود تاريخ تحصيل محفوظ، ومجموع أسماء/مبالغ الكشف يطابق بطاقة الإيراد. اختبار المجال يثبت إدراج 500 من راوند موقوف واستبعاد الأرشيف؛ لم تُقرأ أو تُكتب بيانات إنتاج ولم تتغير صلاحيات المالية.
- [x] إسناد الشهر إلى تاريخ بداية الجروب/Private كما اختار المستخدم؛ لا يوجد تاريخ تحصيل محفوظ في المخطط الحالي، لذلك لا تُنسب المبالغ القديمة إلى شهر قبض مفترض ولا يُضاف سجل دفعات جديد.
- [x] الحفاظ على إدخال/أرشفة/استعادة المصروفات وإجماليات الشهر، مع إبقاء صلاحيات المالك الحالية.
- [x] لكل شهر مختار في الإيرادات يظهر كشف منفصل بالطلاب الذين دخلوا في حساب إيراد ذلك الشهر، مع اسم الطالب ورقم هاتفه والمبلغ المدفوع؛ مجموع الكشف يطابق الإيراد الشهري الحالي، ويظل إسناد الشهر على أساس تاريخ بداية الجروب كما في البيانات الحالية.
- [x] حسابات وتقارير الريتينشن تشمل طلاب الـPrivate وتفاصيلهم وتعرضهم بصفة Private وليس كجروب عادي.
- [x] يبقى إجمالي الطلاب الرئيسي مؤشرًا منفصلًا ولا يُستخدم كبديل عن مقام أو رقم الريتينشن؛ تحافظ تقارير الريتينشن على التمييز بين حساب الشهر وحساب الراوند وقواعد استبعاد المؤرشف وغير النشط كما في المصدر.

## 9. الأمان والأرشفة والنسخ والاسترجاع والتزامن
- [x] الحفاظ على تصدير النسخ الاحتياطية الحالية، نسخة الجروبات/الراوندات المؤرشفة، نسخ JSON، واستعادة JSON الإضافية بدل الاستبدال الكلي، واستعادة الأرشيف.
- [x] الحفاظ على الأرشفة القابلة للاسترجاع، والتحذير من النسخ الاحتياطي القديم، وعدم تحويل الأرشفة إلى حذف نهائي؛ الحذف النهائي إجراء منفصل يتطلب تأكيدين.
- [x] الحفاظ على التراجع/الإعادة العامين وتراجع الجلسة الخاص حيثما ينطبق، والبحث والفلاتر وحالة واجهة كل دور.
- [x] الإبقاء على التخزين المحلي والمزامنة السحابية والدمج بين الحالة المحلية والحالة على Firestore وسياسة تعارض الحضور حسب updatedAt، ومزامنة المعلم والإشعارات، من دون تغيير أسماء المستندات أو مفاتيح البيانات المختصرة.
- [x] عند الحذف النهائي المؤكد لراوند أو جروب أو طالب، يحذف حفظ Firebase مستندات الحضور المركزي التي أزيلت مفاتيحها من الحالة، مع بقاء قواعد Firestore كما هي.
- [x] عدم كتابة/حذف بيانات إنتاج أثناء بناء الواجهة أو فحصها؛ تبقى قواعد Firestore الحالية كما هي خلال هذه المرحلة.

## 10. التواريخ وإخراج Firebase
- [x] توحيد عرض التواريخ في جميع التبويبات بصيغة واضحة وصحيحة، مع عدم تغيير تمثيل التاريخ المخزن أو نوع timestamps المستخدم في المزامنة.
- [x] إنتاج نسخة static قابلة للتسليم إلى Google Cloud Firebase Hosting مع بقاء مسارات login/index/system الحالية؛ المعاينة منفصلة عن الموقع الحي.
- [x] أخذ نسخة احتياطية من ملفات النشر الحالية وإبلاغ المستخدم بخطوات النشر؛ لا يحدث نشر على Firebase الحي قبل مراجعة المعاينة والموافقة الصريحة.


## 11. تصنيف الطلاب ومصدرهم ومؤشرات الرئيسية والمالية وإخفاء المدرس المؤرشف
- [x] عند أرشفة مدرس، لا يظهر اسم المدرس أو جلساته في الحضور والغياب أو تقرير اليوم أو أي تقرير تشغيلي/بحث/مرشح تعيين/جدول ساعات/تنبيه تشغيلي؛ يظهر المدرس المؤرشف في إدارة الأرشيف فقط مع إمكانية استعادته. لا تُحذف حسابات Firebase أو الجروبات/الطلاب غير المؤرشفة، ولا يُغيّر إسنادها. تظل تلك الجروبات والطلاب ضمن أعدادهم الحالية وإيراداتهم حسب قواعد النظام، وتُخفى جلسات المدرس المؤرشف من التقارير التشغيلية إلى أن يُستعاد.
- [x] يدعم سجل الطالب تصنيفًا صريحًا «جديد»، «قديم»، «قديم رجع بعد انقطاع»، ومصدرًا من Facebook أو Instagram أو X/Twitter أو TikTok أو ترشيح صديق أو Google أو الموقع أو WhatsApp أو أخرى مع وصف؛ يدعم سجل الليد المصدر أيضًا. يمكن إدخال/تعديل الحقول على شاشات الطالب والليد، وتظهر على بطاقات الطلاب والليدز وفي فلاتر المصدر المناسبة، وتنتقل عند تحويل الليد إلى طالب. تحافظ السجلات القديمة على توافق `nw` عند غياب التصنيف الصريح دون إعادة كتابة صامتة للبيانات.
- [x] تعرض الرئيسية أعداد طلاب الجروبات وطلاب Private كلًّا على حدة ومجموعهما الحالي للمالك، وتعرض للراوند الحالي عدد الجدد والقدام والعائدين بعد انقطاع مع ملخص المصادر وحالات التجديد المسجلة. تعرض أيضًا أعداد القدام الذين جددوا والذين قرروا عدم التجديد من كل الجروبات وPrivate النشطة. لا يدخل إجمالي الرئيسية في حساب الريتينشن ولا يتغير مقامه. لا يدخل أي طالب/جروب مؤرشف في المؤشرات الحالية.
- [x] يظل الطالب الذي اختار «مش هيجدد» ظاهرًا في تبويب التجديد؛ يظهر حقل «سبب عدم التجديد» عند هذه الحالة ويحفظ الملاحظة في سجل الطالب، ويظل السبب قابلًا للمراجعة والتعديل.
- [x] تعرض صفحة الإيرادات والمصروفات تفصيلًا منفصلًا لإيراد الطلاب الجدد والقدام والقدام العائدين بعد انقطاع في الشهر المحدد، بأسماء الطلاب وأرقامهم ومبالغهم. تستخدم معادلة الإيراد الحالية وشهر بداية الجروب، ولا يتغير الإجمالي أو تطابقه مع الرئيسية.
- [x] في الموبايل، تلتف أدوات «حول الطالب» (نقل الطالب) وحقول «بيانات الطالب» داخل البطاقة والشاشة ولا تُقص أو تفرض عرضًا أفقيًا للبطاقة؛ تبقى الحقول والأزرار قابلة للضغط. لا تتغير بنية أو وظيفة الشاشات الأخرى خارج هذه الطلبات.
- [x] تبقى قواعد Firestore وبيانات الإنتاج دون تغيير، ولا يتم أي نشر تلقائي؛ أُنتج ZIP جديد وأمر واحد للنشر اليدوي إلى Firebase Hosting.


## 12. نسخ الطالب والملاحظات والوصول إلى Private الفارغ
- [x] أضف من بطاقة الطالب إجراءً مستقلًا «نسخ الطالب إلى جروب» لا يحرّك ولا يعدّل الطالب الأصلي. يبدأ المستخدم باختيار راوند نشط ثم يختار جروبًا غير مؤرشف داخل هذا الراوند؛ لا تظهر راوندات أو جروبات مؤرشفة/متوقفة ولا وجهات المدرسين المؤرشفين. النسخة تحصل على معرّف جديد وإسناد المجموعة/الراوند المحددين، وتحافظ على الاسم والهاتف والمستوى والتصنيف والمصدر والملاحظة ومستوى الليفلات؛ تبدأ بحالة دفع غير مدفوع ومبلغ ومتَبقٍ صفر/فارغ، وتجديد «لسه» وبدون سبب أو متابعة/حضور منسوخين، حتى لا تتكرر الإيرادات أو سجلات الطالب الأصلية. يبقى زر «نقل الطالب» الحالي خيارًا منفصلًا دون تغيير.
- [x] تظهر ملاحظة الطالب الموجودة في السجل بجوار اسمه في بطاقات الطلاب ضمن الجروبات وPrivate، ولا تختفي لمجرد أن بطاقة الطالب في شاشة أخرى؛ تقص الملاحظات الطويلة بصريًا مع إتاحة قراءة النص الكامل ولا تسبب تجاوز عرض البطاقة على الهاتف.
- [x] تظهر كل سجلات Private غير المؤرشفة حتى لو لم يكن لها طالب مرتبط بدل إخفائها. تعرض كبطاقة واضحة «جروب Private بدون طالب»، ويمكن للمالك/الأدمن فتحها وتعديلها أو إضافة طالبها الوحيد أو أرشفتها من نفس التبويب. لا تحذف أو تغيّر أي سجل قديم تلقائيًا؛ السجلات المؤرشفة تبقى قابلة للاستعادة من الأرشيف.
- [x] يقتصر هذا التحديث على إجراءات النسخ وعرض الملاحظات وإتاحة Private الفارغ؛ لا تتغير معادلات المالية أو الريتينشن أو حدود طالب واحد في Private أو قواعد Firebase، ولا يحدث نشر تلقائي.


## 13. اختيار الراوند لتصنيف طلاب الرئيسية
- [x] في بطاقة «تصنيف الطلاب» في الرئيسية، أستطيع اختيار أي راوند غير مؤرشف، سواء كان نشطًا أو متوقفًا/منتهيًا؛ لا تظهر الراوندات المؤرشفة. يبدأ الاختيار بالراوند الحالي إذا كان غير مؤرشف، وإلا بأول راوند غير مؤرشف.
- [x] عند اختيار راوند، تتغير أعداد جديد/قديم/قديم رجع بعد انقطاع، قرارات التجديد ومصادر الطلاب لتخص طلاب الجروبات غير المؤرشفة المرتبطة بهذه الراوند فقط؛ إذا لم يكن بها طلاب تظهر الأعداد صفرًا ورسالة مناسبة.
- [x] يظل إجمالي الطلاب الحالي وقسم الراوندات النشطة ومقام/حساب الريتينشن مستقلين ولا يتغيران بتغيير الاختيار؛ التغيير للعرض فقط ولا ينشئ أو يكتب أي بيانات إلى Firebase.
- [x] يظل اختيار الراوند والبطاقة قابلين للاستخدام على الهاتف والكمبيوتر دون قص أو تجاوز العرض.


## 14. تحسينات التشغيل والتقارير المعتمدة
- [x] **تنبيهات التجديد الذكية:** اعرض للمالك والأدمن قائمة عملية للطلاب القريبين من نهاية الراوند، والذين لم يقرروا التجديد، والذين اختاروا «مش هيجدد» مع سبب عدم التجديد؛ وفّر رقم الهاتف وفتح الجروب/Private وإجراء المتابعة أو نسخ الرقم، مع احترام الأرشيف وعدم تكرار التنبيه المنتهي حديثًا.
- [x] **البحث والفلاتر الموحدة:** وسّع البحث الشامل ليبحث باسم الطالب/الليد/الجروب أو رقم الهاتف، وأتح فلاتر النوع والراوند والمصدر والمدرس وحالة الدفع والتجديد حيث ينطبق؛ لا تُظهر سجلات مؤرشفة أو بيانات خارج دور المستخدم، وحافظ على فتح وجهة السجل الصحيح.
- [x] **إشغال الجروبات:** أتح للأدمن/المالك إدخال سعة اختيارية للجروب الجديد أو القائم؛ اعرض عدد الطلاب الحالي والمقاعد المتبقية ونسبة الإشغال، ونبّه إلى الجروبات القريبة من الامتلاء أو ذات العدد القليل. السجلات القديمة بلا سعة تظل بلا حد مفترض، ولا تتغير أهلية إضافة الطلاب إلا إذا حُددت سعة صراحة.
- [x] **متابعة العملاء المحتملين:** اعرض للمالك/الأدمن قائمة منفصلة بمتابعات الليدز المستحقة اليوم والمتأخرة، مع حقل «سبب عدم تحديد المتابعة» قابل للإدخال والتعديل عند عدم وجود موعد، وأظهر السبب أو «غير مسجل» بوضوح؛ استمر في احترام التصنيف النهائي/غير المهتم وسجل تاريخ المتابعة وأزرار النسخ والإكمال الحالية.
- [x] **أداء المدرسين:** في التقرير الشهري أظهر ساعات الخطة الأسبوعية، الساعات الفعلية، تقدير الخطة الشهرية نسبةً لأيام الشهر، مقدار الفرق/نسبة الإنجاز، وعدد الجلسات الملغاة؛ حافظ على استبعاد الجلسات الملغاة والجروبات/المدرسين المؤرشفين من الساعات التشغيلية حيث تنطبق القواعد الحالية.
- [x] **إخفاء اختيار الراوند للمدرس:** في تبويب الحضور والغياب لا يظهر للمدرس حقل اختيار الراوند؛ يرى قائمة الجروبات والـPrivate المسندة إليه فقط. جرس المدرس يعرض فقط تنبيه قرب نهاية جروباته النشطة، ولا يعرض الليدز أو قرارات تجديد الطلاب أو المدفوعات أو بيانات جروبات مدرس آخر. تظل فلاتر الراوند والمدرس والتنبيهات العامة متاحة للمالك/الأدمن.
- [x] **إزالة المدرس بأمان:** وفّر إجراء إزالة/أرشفة للمدرس في إدارة المدرسين؛ يؤدي الإجراء إلى أرشفة قابلة للاستعادة فقط، ولا يحذف حساب Firebase أو الجروبات والطلاب والتكليفات أو السجلات المالية، ويخفي جلساته من التشغيل وفق السياسة المعتمدة.
- [x] **كشف الإيرادات:** أضف زرًا لإخفاء الطالب من كشف الشهر المختار فقط، مع حفظ الاستبعاد حسب الشهر وإتاحة إعادة الصف؛ يظل ملف الطالب ومبلغ الدفع وأي سجلات أخرى دون تغيير، ولا ينقص أو يتغير إجمالي إيراد الشهر بسبب إخفاء الصف. عند الضغط على اسم الطالب يفتح الجروب أو Private المرتبط به.
- [x] لا تغيير لقواعد Firestore أو حذف بيانات فعلية أو نشر تلقائي؛ ZIP وأمر Cloud Shell لا يُجهزان إلا إذا طلبهما المستخدم صراحة لهذه الجولة.


## 16. نسخ أرقام القوائم
- [ ] أضف زر «نسخ كل الأرقام» في صفحة التجديدات، وصفحة الليدز، وصفحة العملاء الجدد/الراوند القادمة، وصفحة عملاء تحديد المستوى. ينسخ أرقام الهواتف للسجلات الظاهرة حاليًا فقط بعد تطبيق البحث والفلاتر والترتيب في كل صفحة، رقمًا واحدًا في كل سطر؛ يتجاهل السجلات بلا رقم ويزيل تكرار الرقم حتى لو اختلفت علامات المسافات أو الشرطات مع الحفاظ على شكل الرقم الأصلي المنسوخ. اعرض عدد الأرقام المنسوخة ورسالة نجاح أو تعذر؛ لا تغيّر بيانات الطلاب أو الليدز ولا تخفي/تنقل أي سجل، واجعل الزر مناسبًا للموبايل.
